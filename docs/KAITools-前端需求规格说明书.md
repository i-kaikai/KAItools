# KAITools 前端需求规格说明书

> 状态：本地优先版本基线 + 后续前端规划
>
> 本文只定义前端产品体验、状态与接口边界。后端账户、同步和生产部署属于后续阶段，不是当前 Web 或桌面端可用性的前提。

## 变更记录：本地服务与笔记工作台

以下内容已取代本文中“当前聚焦工具”“首页快捷入口”和“后续本地笔记”的旧描述：

- 当前注册 20 个工具，新增“超级计算器”和桌面限定“剪切板历史”。首页保留 3D 工具卡片、工作台概览、当前会话工具、分类、系统状态和仓库入口；右侧保留唯一置顶 Markdown 笔记，不展示快捷方式或废弃的笔记上下文。
- 侧栏是快捷方式的唯一展示区，初始折叠。工具列表末尾的“管理快捷方式”可搜索全量工具、添加/移除、拖拽排序、键盘排序和恢复默认，限制为 1 至 12 项。
- 桌面笔记只写入受控 `data/notes/`，Web 笔记只写入 IndexedDB；均不支持外部文件夹。笔记层级为“笔记本 -> 文件夹 -> Markdown 笔记”，支持编辑、预览、置顶、搜索、移动和递归删除确认。
- 普通应用固定连接 `https://tools.imkai.top/api` 用于账户与同步；服务不可用或用户未登录时，应用保持全本地可用，不提示用户检查本机服务。仅隐藏开发者模式可启用本机回环服务覆盖，默认 `http://127.0.0.1:8080`；客户端固定请求 `/api/...`。
- 品牌统一为 `KAI`、`Keep Approaching Ideal`、`始终靠近理想`。动效仅用于 3D 卡片和偶发的按钮/弹层反馈；编辑、查找和快捷键保持即时。
- 侧栏齿轮打开设备级应用设置：主题、粒子高质量/均衡/关闭、减少动态效果、侧栏启动方式、固定标签恢复、编辑器字号与自动换行。首页卡片管理与快捷方式管理分别保留原入口。
- 桌面版的 `Esc` 和全局唤起快捷键可隐藏窗口到通知区；前台再次按快捷键继续隐藏，托盘菜单提供显示与退出，标题栏 `X` 直接退出。剪切板历史默认记录纯文本、仅内存保存、退出时清空，隐藏到托盘后持续运行。

## 1. 目标与原则

KAITools 是面向开发者的本地工具工作台。前端必须同时服务于 Windows 桌面版和浏览器版：工具计算优先在前端完成，未启动后端服务时仍可完整使用除 Windows 系统能力外的全部工具。

产品体验遵循以下原则：

1. **本地优先**：打开应用即可工作，不要求登录、网络、Java 服务或数据库。
2. **工具优先**：首页负责快速进入工具；编辑器、结果和操作按钮优先于装饰元素。
3. **快捷方式不等于全量工具**：侧栏仅展示用户固定的常用工具；搜索和首页分类始终可访问全部注册工具。
4. **可恢复**：主题、侧栏状态、性能和编辑器偏好、快捷方式和固定标签在本地保存；未固定标签和工具原文默认只在当前内存会话中存在。
5. **不上传敏感内容**：JSON、Java、SQL、Hosts、文件和 MD5 原文在当前阶段不通过前端发送到远端。
6. **高频操作即时**：输入、编辑、标签切换、查找、快捷键不使用延迟或装饰性过渡。

## 2. 范围与版本边界

### 2.1 当前版本必须支持

- Vue 3、TypeScript、Vite、Pinia、CodeMirror 6、Lucide、Three.js。
- Windows 桌面版：Python + pywebview + WebView2 提供受控本地桥接能力。
- 浏览器版：无 pywebview 时自动使用浏览器本地存储，不阻塞工具使用。
- 20 个本地工具：JSON、JSON 对比、JSON / JavaBean、Java 转义、日期转换、Base64 文本、Base64 图片、Base64 文件、Crontab 生成器、SQL 美化、YAML 美化、XML 格式化、文本比较、文本统计、正则工作台、笔记、Hosts、超级计算器、剪切板历史、MD5 摘要；以及首页工作台、侧栏快捷方式、全局搜索、多标签、主题和仓库入口。
- 纯前端工具计算、编辑器双栏拖动、可编辑输出、查找/替换及匹配计数。

### 2.2 本阶段不纳入

- 账户注册、登录、邮箱验证码、GitHub/微信授权和第三方会话。
- 云端同步、远端 Java 服务依赖、数据库依赖、协同编辑和在线分享。
- 任意文件系统读写、任意命令执行、任意 URL 打开等桌面桥接能力。
- 自动更新、在线插件市场、动态脚本插件和云端工具原文备份。

## 4. 首页工作台

### 4.1 首屏

- 首页默认直接展示工作台，不保留“进入工具台”的中间页。
- 首次启动默认折叠侧栏；之后可在应用设置中选择记住状态、默认收起或默认展开。
- 顶部显示产品名称、当日日期、工具数、已打开标签数和快捷方式数。
- 首屏主体由“本地工具台”说明、3D 工具卡片轨道和当前聚焦模块组成。
- 用户点击卡片或“打开模块”后，新建或切换至对应工具标签。

### 4.2 3D 工具卡片轨道

- 卡片从编译期工具注册表读取，不允许首页维护第二份工具清单。
- 卡片必须展示工具名、简短说明、图标和工具色，不展示工具输入内容。
- 自动缓慢移动；鼠标悬停时停止自动移动，滚轮增加旋转速度，拖拽可以直接改变位置并保留惯性。减少动态效果时停止自动移动，手动拖拽和滚轮仍可即时操作。
- 鼠标/键盘聚焦某张卡片时，右侧“当前聚焦”模块同步更新，粒子卫星使用该工具色反馈。
- 卡片点击、触摸、滚轮和拖拽必须区分：拖动后不能误打开工具。
- 小屏幕应缩小为单列舞台，不因 3D 布局导致水平滚动或覆盖底部导航。

### 4.3 首页辅助区

- 工作台概览显示当前已打开标签、笔记本数量和当前会话工具；点击工具可直接切换或打开对应标签。
- 系统状态在桌面版显示 CPU、内存、电量、工作区数据状态、版本、WebView2 和数据目录；浏览器版显示浏览器、网络与本地存储能力。
- Gitee 与 GitHub 使用各自官方图标，桌面版通过固定桥接地址打开系统浏览器，Web 版通过 `noopener,noreferrer` 打开新标签。
- 工具分类展示全部工具，按数据格式、编码转换、开发辅助、文本处理、系统工具分组。

## 5. 侧栏、搜索与标签

### 5.1 侧栏快捷方式

- 系统提供默认快捷工具；用户可在全局搜索中添加或移除，至少保留一个、最多 12 个。
- 展开状态展示图标、中文名称、中文用途说明与新建标签按钮；折叠状态只展示图标与可访问名称。
- 侧栏筛选仅筛选当前快捷方式；未固定工具应通过全局搜索或首页分类访问。
- 后续本地阶段增加快捷方式拖拽排序、恢复默认和在首页管理的能力。

### 5.2 全局搜索

- 入口：展开侧栏右侧放大镜、折叠侧栏搜索按钮、`Ctrl/Cmd + K`。
- 输入支持中文名称、英文关键词、工具用途和分类关键词；搜索结果均为中文 UI 文案。
- 结果支持键盘上下选择、Enter 打开、Escape 关闭和快捷方式开关。
- 弹层在桌面端居中，在移动端保留安全边距；不得遮挡输入焦点或产生页面水平滚动。

### 5.3 多标签

- 首页为单例且不可关闭；非单例工具可新建多个标签。
- 标签支持激活、关闭、固定、关闭当前、关闭其他、关闭右侧和关闭全部。
- 固定标签保存其工作区元数据并在重启后恢复；不固定标签不强制持久化。
- 标签栏内容溢出时只允许横向滚动，不允许引发页面整体滚动条。

## 6. 通用工具交互

### 6.1 编辑器与双栏布局

- 所有具有输入/输出两个文本区域的工具，两侧都应允许编辑，除非工具本身明确是只读预览。
- 双栏宽度可由用户手动拖动；窄屏转换为纵向布局，拖动条转为垂直尺寸调节。
- 输出编辑后必须回写工具状态，并驱动对应的树、关系图、预览或统计结果更新。
- CodeMirror 使用统一主题、错误行列、语法色彩、复制和清空行为。

### 6.2 查找与替换

- 所有复用 `CodeEditor` 的区域使用中文查找面板。
- 空查询显示“输入关键词”；有结果而未定位显示“未定位，共 N 个”；定位后显示“第 N 个，共 M 个”。
- 支持大小写、正则、全字匹配、上一个、下一个、替换和全部替换。
- 大文本的匹配统计必须可取消、分片执行；关闭面板或内容变化后不得显示过期统计。
- 查找面板停靠在编辑器上方，不覆盖代码内容；窄宽度时可换行但关闭按钮始终可见。

### 6.3 状态与错误

- 成功、失败、权限不足和浏览器拦截使用中文 Toast，错误信息不泄露本地路径、请求凭据或工具原文。
- 工具输入不合法时显示行列或字段级错误；不得清空用户输入或覆盖上一次可编辑结果。
- 所有加载、空状态和桌面限定状态都应有明确中文文案。

## 8. 视觉与动效规范

### 8.1 视觉方向

- 采用深色、克制、专业的开发工具界面，不使用营销页布局或大面积空白。
- 首页通过粒子、深度、透明材质、卡片前后层级表达空间感；工具页保持平静、清晰和高信息密度。
- 色彩以中性深色为基底，不同工具用有限的功能色区分，避免单一色相铺满界面。
- 使用产品既有 KAITools 标识、Lucide 和 Gitee/GitHub 官方图标；不复制任何外部作品的版式、素材或品牌资产。

### 8.2 动效规则

- 首页允许：粒子缓慢呼吸、卡片空间移动、鼠标视差、卡片悬停边界反馈和 180-260ms 的一次性进入反馈。
- 交互动作优先使用 `transform` 与 `opacity`，避免频繁触发布局计算。
- 标签切换、输入、查找、快捷键、复制、编辑器选择和表单验证不得添加装饰性动效。
- 鼠标悬停反馈控制在 120-180ms，弹层与 Toast 控制在 125-200ms；不得使用弹跳、长时间转场或无意义循环动画。
- 必须尊重 `prefers-reduced-motion`：关闭入场动画、自动旋转、呼吸与视差，保留点击和键盘功能。
- 仅在精细指针设备启用 hover 专属效果；触摸设备依赖拖拽、滚动与可点击控件。

### 8.3 性能预算

- 粒子画布仅在首页激活时挂载，页面隐藏时暂停帧循环，组件卸载时释放 Three.js 几何体、材质和渲染器。
- 首页系统状态使用运行环境专属数据源：桌面桥接仅暴露 CPU、内存、电量、工作区数据及 Windows/应用受控诊断；浏览器只读取标准 Web API，未知字段显示不可用。
- 渲染像素比限制在合理上限，避免高 DPI 大屏造成不必要 GPU 开销。
- 工具页按需异步加载；新增重量级可视化库前，先验证首屏包体、内存和 WebView2 性能。

## 9. 跨端与本地数据

### 9.1 数据归属

| 数据 | 桌面版 | 浏览器版 | 当前是否远端同步 |
| --- | --- | --- | --- |
| 主题、侧栏折叠、快捷方式 | EXE 同级数据目录 | `localStorage` | 否 |
| 固定工作区标签 | EXE 同级数据目录 | `localStorage` | 否 |
| 未固定工具输入 | 内存 | 内存 | 否 |
| Hosts 内容与备份 | Windows 系统文件与本地备份 | 不可用 | 否 |
| 工具原文、文件、图片、日志 | 本地或内存 | 本地或内存 | 否 |

### 9.2 桌面桥接

- 前端只能通过统一 `desktopApi` 调用白名单能力。
- 桌面 API 返回统一结果：`{ ok, data?, error?: { code, message, details? } }`。
- 前端不得传入任意文件路径、命令、URL 或提权参数；仓库链接为固定常量。
- Hosts 是唯一需要 Windows 管理员权限的工具，Web 端一律不模拟或降级为系统文件编辑。

## 11. 后续前端分期

### P1：纯本地体验增强

- 快捷方式拖拽排序、恢复默认、首页快捷入口管理。
- 首页可配置卡片（内部工具或安全 HTTPS 链接）、排序、启停和本地存储。
- Markdown 笔记本、文件夹、笔记、固定笔记和版本恢复，全部只保存在本地。
- 新工具通过注册表接入，补齐类别、关键词、图标、默认状态、快捷方式与首页展示。

### P2：账户和同步前端准备

- 保留无登录本地模式；登录后必须询问“使用本地数据、使用云端数据或创建冲突副本”。
- 仅同步偏好、快捷方式、首页卡片、笔记和固定标签元数据；不上传任何工具原文或系统文件内容。
- 提供同步状态、离线队列、冲突可见性和手动重试 UI。

### P3：远端服务接入

- 远端 Java 服务可用时，前端通过独立 `remoteApi` 接入；不可用时必须无感回退到本地模式。
- 桌面端登录通过系统浏览器完成，不嵌入第三方授权页面，不自动启动 Java 或 PostgreSQL。
- 服务器、数据库、邮件、GitHub/微信绑定、生产域名和部署策略需另行评审，不由前端自行假设。

## 12. 测试与发布验收

- Vitest：工具算法、状态持久化、快捷方式限制、查找计数、桥接错误和浏览器外链拦截。
- Playwright：桌面/Web、浅色/深色、上述关键尺寸、移动端、焦点、文本溢出、卡片滚轮/拖拽和减少动态效果。
- 桌面：pytest 覆盖桥接白名单、配置原子写入、Hosts 安全规则；Windows 10/11 手工验证 UAC 和 WebView2 缺失提示。
- 每次前端发布至少执行类型检查、单元测试、桌面 E2E、Web 构建和 Web E2E。
- 构建产物、测试截图和本地数据目录不提交到源码仓库，除非发布流程明确要求。

## 13. 需求变更规则

1. 新增工具、可同步数据、第三方登录或桌面桥接接口必须先更新本文档。
2. 修改工具 ID、浏览器存储键、桌面数据目录或 IPC 名称前，必须提供迁移方案。
3. 任何需要网络、账户、数据库或管理员权限的功能，都必须保留明确的本地离线行为。
4. 视觉重构以任务完成效率、可访问性、响应式和性能为验收标准，动效不能成为功能阻塞项。

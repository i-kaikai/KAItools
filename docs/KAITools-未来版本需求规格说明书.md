# KAITools 未来版本需求规格说明书

> 2026-08-26 更新：普通应用固定连接 `https://tools.imkai.top/api` 用于账户与同步；服务不可用或未登录时保持全本地可用。本机联调地址默认 `http://127.0.0.1:8080`，仅隐藏开发者模式可作为覆盖项启用；接口统一使用 `/api/...`，例如 `GET /api/health`。后端仍是独立 Java 21 进程，数据库配置缺失时拒绝启动，桌面和 Web 离线模式不受影响。

## 1. 背景与目标

KAITools 是面向开发者的本地工具工作台。产品已经提供 JSON、编码与摘要、媒体和文档转换、开发调试、效率辅助、文本处理、格式化和 Hosts 等本地工具。后续版本的目标不是把本地工具改造成必须联网的 SaaS，而是在不破坏离线体验的前提下，逐步增加可选的账户、工作台个性化、跨设备同步和 Markdown 笔记能力。

本期需求基线确立以下原则：

1. 离线优先。未启动或不可访问后端时，桌面端和 Web 端仍可使用已有本地工具。
2. 前后端分离。桌面应用不自动拉起 Java、PostgreSQL 或数据库隧道；后端是独立部署、独立运维的服务。
3. 用户可控。任何将本地数据迁移到云端的动作都必须由用户明确确认，不能静默上传。
4. 最小化同步。仅同步用户明确需要跨设备使用的工作台数据，不上传工具原文、系统文件、文件内容和设备信息。
5. 工具优先。账户、首页和动效服务于高频开发工作，不应遮挡编辑器、降低搜索效率或妨碍键盘操作。

## 2. 范围与状态

### 2.1 已具备的本地能力

当前版本已经具备下列能力，后续迭代必须保持兼容：

- 20 个本地工具模块：JSON、JSON 对比、JSON / JavaBean、Java 转义、日期转换、Base64 文本、Base64 图片、Base64 文件、Crontab 生成器、SQL 美化、YAML 美化、XML 格式化、文本比较、文本统计、正则工作台、笔记、Hosts、超级计算器、剪切板历史、MD5 摘要。
- 多标签工作区、固定标签、右键关闭当前/其他/右侧/全部标签、全局工具搜索、主题切换和首页工具入口。
- 首页工作台概览与系统状态：桌面端显示 CPU、内存、电量与工作区数据状态，浏览器端显示可用的本地能力。
- 左右双栏工具的双侧可编辑、分割线拖动、CodeMirror 查找替换及“当前第几个 / 一共多少个”的匹配计数。
- JSON 格式化、树视图、关系图、节点内容编辑与回写。
- 桌面端的安全 Hosts 编辑、UAC 保存、备份和恢复；Web 端不具备修改系统 Hosts 的权限。
- Windows 10/11 x64 免安装桌面包，以及浏览器 `localStorage` 本地状态。

### 2.2 已建立但尚未接入产品的后端基线

独立的 `kaitools-api` 仓库已建立 Java 21、Spring Boot 3、Spring Security、PostgreSQL、Flyway、MyBatis-Plus 工程，并按 MVC + DDD 分层。数据库连接缺失或不完整时，后端必须拒绝启动；前端不因此受到影响。

当前后端仅包含数据库迁移和开发验证用工作台接口，不能视作正式账户服务。特别是登录、用户会话、同步队列、冲突处理、生产级鉴权和前端接入均未完成。

### 2.3 本文定义的未来范围

- 可选登录与账户体系。
- 工作台偏好、侧栏快捷方式、首页卡片与 Markdown 笔记的跨设备同步。
- 离线变更队列、版本控制和冲突处理。
- 基于当前设计方向的前端体验重构与可访问性完善。
- 从本地验证到远程服务的发布与运维边界。

### 2.4 明确不在首期范围

- 强制登录、强制联网或将本地工具改为服务端计算。
- 用户工具输入、Hosts 内容/备份、文件/图片 Base64 内容、日志、设备路径、WebView2 版本等敏感或设备相关数据的云端同步。
- GitHub、微信等第三方登录在首期直接上线。
- 云端文件存储、多人协作、公开分享、富文本笔记、图片上传、动态第三方插件、自动更新和付费体系。
- 将后端、PostgreSQL 或数据库隧道打进 Windows 桌面安装包。

## 3. 产品模式

| 模式 | 用户是否登录 | 后端是否可用 | 可用能力 | 数据位置 |
| --- | --- | --- | --- | --- |
| 本地离线模式 | 否 | 否或不可达 | 全部本地工具、标签、主题、侧栏快捷方式、本地首页 | 桌面端 `data`；Web 端浏览器本地存储 |
| 本地在线未登录模式 | 否 | 可达 | 与离线模式一致；不自动创建账户或上传数据 | 本地 |
| 已登录同步模式 | 是 | 可达 | 本地能力 + 已选择数据的同步、冲突处理、跨设备恢复 | 本地缓存 + 用户远程工作区 |
| 后端开发模式 | 不面向最终用户 | 本地或测试环境可达 | 数据库迁移、接口联调、测试工作台接口 | 测试 PostgreSQL |

### 3.1 状态切换规则

1. 应用启动默认进入本地模式，不因网络异常弹出阻断式登录窗口。
2. 用户主动选择“登录/同步”后，才开始账户流程。
3. 首次登录且检测到本地可迁移数据时，必须让用户选择“上传本地数据”“使用云端数据”或“暂不同步”。
4. 远端不可达时，已登录客户端继续读取和写入本地缓存，并清晰显示“等待同步”；不得覆盖本地修改。
5. 退出登录只清除本地身份凭据，不删除用户本地工具数据；清理本地同步缓存必须二次确认。

## 4. 用户与核心场景

### 4.1 目标用户

- 日常处理 JSON、Java、SQL、时间、编码和正则的 Java/前端/测试工程师。
- 需要保留本地隐私数据，同时希望在多台设备之间复用工作台布局的个人开发者。
- 不希望安装数据库或配置后端即可使用工具的 Windows 桌面用户。

### 4.2 关键场景

1. 用户在无网络环境打开桌面端，继续使用 JSON、时间戳和 Java 转义工具。
2. 用户在首页将常用模块添加为侧栏快捷方式，其他工具仅通过搜索或完整工具目录打开。
3. 用户登录后，选择将侧栏、首页卡片和 Markdown 笔记同步到另一台设备。
4. 两台设备离线修改同一条笔记，恢复网络后保留双方内容并提示用户处理冲突，不静默丢失任一版本。
5. 用户从 Web 端打开工具；涉及 Hosts 的模块明确提示需使用桌面端，不提供伪造的系统写入能力。

## 5. 前端体验与交互需求

### 5.1 设计方向

前端延续“沉浸但克制的开发工作台”方向：参考 ToolKnit 一类工具化产品的信息密度与 Phenomenon Studio 风格的空间层次、材质和交互反馈，但不复制其视觉资产或将作品集式效果带入编辑器工作流。

- 首页是进入工具、工作台概览、置顶笔记和本地设备状态的操作台，不是营销落地页。
- 允许使用可交互的 3D 粒子/模块卡片作为首页背景和工具入口，但编辑器页保持安静、可扫描。
- 动效必须有明确目的：首屏状态建立、模块聚焦、拖动反馈、弹层进入/退出。高频标签切换、搜索和编辑不增加延迟。
- 遵从 `prefers-reduced-motion`；关闭动态效果后，核心信息和所有操作必须保持可用。
- 采用 CSS 变量、Lucide 与轻量自有组件，不引入大型 UI 框架；页面不使用装饰性的渐变球、无意义的浮层卡片或会遮挡内容的查找面板。

### 5.2 侧栏快捷方式

侧栏是用户的快捷方式集合，不是全部工具清单。

1. 首次初始化添加系统默认快捷方式；默认集合由产品配置维护。
2. 用户可从完整工具注册表中搜索并添加、删除、排序、隐藏快捷方式。
3. 用户可一键恢复系统默认，但需提示该操作会替换当前快捷方式顺序。
4. 全部工具仍可通过全局搜索、首页分类和工具目录打开。
5. 桌面与 Web 均支持快捷方式编辑；已登录状态下该配置可同步。
6. 折叠侧栏必须保留首页、搜索、主题和仓库入口等关键操作的可发现性与键盘焦点。

### 5.3 首页卡片

首页在保留当前工具模块动态卡片的基础上，增加可配置的工作台卡片区。

- 卡片类型仅限“内部工具入口”和“HTTPS 链接”。
- 每张卡片包含标题、描述、强调色、排序、启用状态和目标。
- 禁止 `javascript:`、本地路径、脚本命令、任意文件协议和隐藏跳转。
- 支持新增、编辑、删除、排序、启用/停用、恢复默认卡片。
- 卡片可在未登录时仅保存本地；登录后由用户选择是否同步。

### 5.4 Markdown 笔记

首期提供轻量 Markdown 笔记，而非知识库或富文本协作产品。

- 层级：笔记本 -> 文件夹 -> Markdown 笔记。
- 支持标题、正文、排序、固定、最近更新与基础全文搜索。
- 每个用户最多一条固定笔记，首页展示该固定笔记摘要。
- 保存时生成版本号；同步冲突时生成冲突副本或要求用户选择保留版本。
- 首期不支持公开链接、多人编辑、图片上传、附件、富文本和第三方嵌入。

### 5.5 可访问性与响应式

- 支持键盘导航、可见焦点、语义化按钮、Toast 和查找状态的屏幕阅读器提示。
- 在 `960x640`、常规桌面宽度、`1600x900` 及移动 Web 宽度下不截断关键操作。
- 编辑器区域优先保证可见内容；查找、设置和登录弹层不能覆盖正文且无法关闭。
- 桌面端使用原生窗口边框；顶部浏览器或 WebView2 留白必须受主题变量控制，不能出现突兀的白色区域。

## 6. 账户与身份需求

### 6.1 首期登录方式

首期采用无密码邮箱验证码登录：

1. 用户输入邮箱，服务端进行格式、频率和风险校验。
2. 服务端生成六位一次性验证码，保存不可逆摘要与十分钟有效期。
3. 用户提交验证码成功后，首次用户自动创建账户；已有用户创建会话。
4. 首次成功登录必须记录服务条款和隐私政策的同意版本与时间。
5. 验证码支持次数限制、重发冷却、失败次数限制和过期处理；错误提示不得泄露邮箱是否已注册。

### 6.2 会话与客户端存储

- Web：短期访问令牌放在内存，刷新令牌使用 `HttpOnly`、`Secure`、`SameSite` Cookie；不得存储在 `localStorage`。
- Windows 桌面端：登录经系统浏览器完成回调；刷新令牌仅保存在 Windows Credential Manager，不保存到 `data` 目录或日志。
- 前端本地工具状态继续使用现有本地存储；身份信息和工具原文不可混入同一持久化对象。
- 服务端会话支持刷新、主动退出、全部设备退出和过期清理。

### 6.3 延后项

- GitHub 与微信只在正式账户体系稳定后作为“已登录账户绑定”的独立需求评审，不与首期邮箱验证码并行实现。
- 第三方授权密钥、微信开放平台资质、邮件发件域名、DNS、SPF/DKIM/DMARC 与生产回调地址均属于部署阶段，不在本地开发期启用。

## 7. 同步与冲突处理

### 7.1 允许同步的数据

- 用户偏好：主题、语言、侧栏折叠状态等非设备敏感配置。
- 侧栏快捷方式。
- 首页工作台卡片。
- Markdown 笔记本、文件夹、笔记及笔记版本。
- 已明确纳入同步范围的工作台布局元数据。

### 7.2 禁止同步的数据

- 任意工具输入与输出原文，包含 JSON、Java、SQL、正则、MD5 原文、日期输入等。
- Hosts 文件正文、差异、备份、摘要及任何系统文件内容。
- Base64 文件/图片内容、文件路径、拖入文件元数据。
- 桌面日志、WebView2 版本、机器名、用户目录、设备路径、UAC 状态和本地数据库连接信息。

### 7.3 同步协议

1. 每条可同步记录包含稳定 ID、`revision`、`updatedAt` 和所有者 ID。
2. 客户端离线修改写入本地队列，按操作顺序在网络恢复后提交。
3. 服务端仅接受基于当前 `revision` 的更新；版本不一致返回冲突，不执行静默覆盖。
4. 对笔记正文，客户端创建“冲突副本”并保留原版本；对快捷方式和卡片，展示本地/云端选择或按产品规则生成可恢复副本。
5. 同步状态分为“已同步”“等待同步”“存在冲突”“同步失败”；用户可查看失败原因并手动重试。
6. 退出登录或切换账户时，待同步队列必须由用户选择保留、丢弃或先完成同步。

## 8. 技术架构

### 8.1 工程边界

```text
E:\prodect\codingTool\
  kaitools-web/    客户端仓库
    frontend/      Vue 3 + TypeScript + Vite，Web 与桌面共用界面
    desktop/       Python 3.13 + pywebview + WebView2，仅提供 Windows 本地能力
    branding/      产品标识与发布资源
    scripts/       前端、桌面验证、打包与冒烟测试
  kaitools-api/    后端仓库
    src/           Java 21 + Spring Boot 3 API、MVC + DDD 分层与 Flyway 迁移
    scripts/       后端测试与 JAR 构建
```

前后端采用独立 Git 仓库、独立发布节奏和独立 CI。唯一跨仓库运行时契约是 HTTPS/HTTP 上的 `/api/...`；契约变更必须同步维护客户端调用、后端测试和版本说明。

### 8.2 前端与桌面端

- Vue 3、TypeScript、Vite、CodeMirror 6、Lucide。
- 前端工具计算优先在浏览器完成；通过统一 `desktopApi` 调用桌面白名单能力。
- 桌面桥接仅允许窗口、配置、固定工作区、Hosts 和固定仓库链接等受控操作；不得暴露任意命令、任意文件写入或任意 URL 打开接口。
- 远程 API 通过独立 `remoteApi` 接入；不存在或不可达时自动回退本地模式，不影响工具功能。

### 8.3 后端：MVC + DDD

后端采用 Java 21、Spring Boot 3、Spring Security、PostgreSQL、Flyway 和 MyBatis-Plus。

```text
adapter/in/web/    HTTP Controller、请求/响应 DTO、异常转换
application/       用例服务、事务边界、命令和查询编排
domain/            聚合、实体、值对象、领域规则、仓储端口
infrastructure/    PostgreSQL/MyBatis-Plus 仓储、邮件、安全、缓存等适配器
shared/            统一响应、错误码、公共基础类型
config/            Spring、安全、数据库、可观测性配置
```

- Controller 不直接使用 Mapper，不承载业务规则。
- Application Service 只依赖领域端口，负责用例流程与事务编排。
- Domain 不依赖 Spring、MyBatis-Plus 或 PostgreSQL。
- Infrastructure 实现仓储端口和外部系统适配。
- 所有 API 返回统一结构：`{ ok, data?, error?: { code, message, details? } }`。

### 8.4 数据库与配置

- PostgreSQL 是后端唯一的持久化数据库；桌面端不内置、不启动、也不要求安装 PostgreSQL。
- Flyway 管理数据库结构；迁移版本只增不改，空库可从零迁移。
- 后端必须检查完整 `spring.datasource.url`、`username`、`password`。配置缺失、URL 非完整 PostgreSQL JDBC URL 时拒绝启动，不提供内存数据库降级。
- 配置使用单一 `application.yml` 作为结构入口，真实连接信息与密钥由环境变量或部署平台注入。不得把密码、令牌、生产 URL 写入 Git。
- 数据库连接、Flyway、MyBatis 映射与 JSONB 类型处理必须有集成测试；测试数据库可通过本地隧道访问，但隧道脚本不进入桌面产品。

### 8.5 远程部署边界

- 目标域名：`tools.imkai.top`，最终前端与 API 的具体路由形态（同域 `/api` 或独立 API 子域名）在部署评审时确认。
- 开发期仅允许本地或测试环境验证，不发送真实邮件、不调用第三方 OAuth、不修改 DNS、不申请证书、不变更生产服务器。
- 生产发布前必须完成域名、备案、HTTPS、邮件发件域名、数据库备份、日志脱敏、监控告警和回滚演练等运维前置条件。

## 9. 数据模型目标

后端数据模型以用户为所有权边界。首批目标实体如下：

| 实体 | 关键字段与职责 |
| --- | --- |
| `app_user` | 用户 ID、邮箱、显示名、状态、条款同意时间 |
| `email_challenge` | 邮箱验证码摘要、用途、次数、过期时间、消费状态 |
| `auth_session` | 用户设备会话、刷新令牌摘要、过期与撤销状态 |
| `oauth_identity` | 未来 GitHub/微信等第三方身份绑定 |
| `user_preference` | 用户级偏好 JSONB、版本号、更新时间 |
| `sidebar_shortcut` | 工具 ID、排序、启用状态 |
| `dashboard_card` | 卡片类型、目标、文本、颜色、排序、版本号 |
| `notebook` / `note_folder` | 笔记本与文件夹层级 |
| `note` / `note_revision` | Markdown 笔记、固定状态、乐观锁版本与历史快照 |
| `workspace_tab` | 可选择同步的工作台标签元数据，不保存工具原文 |
| `operation_log` | 脱敏的模块、动作、耗时、错误码和摘要 |

所有用户数据表必须具备明确的用户所有权校验；接口不得仅依赖客户端传入的用户 ID。

## 10. 安全与隐私要求

- 传输使用 HTTPS；生产环境拒绝非 HTTPS API 来源。
- 密码、验证码、刷新令牌只保存摘要；日志不得记录令牌、邮箱验证码、工具原文、完整 Hosts 内容或数据库连接字符串。
- API 采用最小权限、限流、输入长度/类型白名单、统一错误码和 CORS 精确来源控制。
- 前端外链只允许明确的 HTTPS 白名单或用户明确保存的 HTTPS 卡片目标，窗口打开需使用 `noopener,noreferrer`。
- Hosts 权限提升继续保持“固定系统路径、待写内容摘要、时效校验、原子替换和备份”的桌面限定模型。
- 同步删除采用可恢复策略或延迟清理，避免网络抖动导致不可逆数据丢失。

## 11. 接口规划

正式 API 在实现前需单独维护 OpenAPI 契约。建议的资源边界如下：

| 领域 | 计划接口能力 |
| --- | --- |
| 认证 | 发起邮箱验证码、校验验证码、刷新会话、退出当前/全部设备、查询当前用户 |
| 偏好 | 查询和带 `revision` 更新用户偏好 |
| 快捷方式 | 查询、替换排序、恢复默认 |
| 首页卡片 | 查询、新增、编辑、删除、排序、启停 |
| 笔记 | 笔记本/文件夹/笔记 CRUD、固定、搜索、版本历史、冲突副本 |
| 同步 | 拉取变更、批量提交操作、冲突响应、同步游标 |

所有写接口需要幂等请求标识或版本号；冲突响应必须携带服务端版本、当前版本号和可供客户端恢复的最小信息。

## 12. 交付阶段与验收

### 阶段 A：本地体验整理

- 完成侧栏快捷方式编辑、本地首页卡片和 Markdown 笔记的本地存储模型。
- 保持无后端状态下的完整可用性。
- 验收：桌面与 Web 离线启动、编辑、重启恢复；`960x640`、常规桌面、宽屏和移动 Web 无关键溢出。

### 阶段 B：后端基础与本地联调

- 完成正式领域模型、数据库迁移、开发鉴权替换方案与 OpenAPI 契约。
- 使用独立测试 PostgreSQL 验证 Flyway、JSONB、事务和乐观锁。
- 验收：无数据库配置后端拒绝启动；空库迁移成功；前端无需后端仍可运行。

### 阶段 C：账户与同步闭环

- 实现邮箱验证码、本地/云端迁移选择、同步队列与冲突处理。
- 邮件仅使用本地日志或邮件捕获工具，不调用真实发件服务。
- 验收：两客户端离线修改、恢复网络、冲突可见且任一版本不丢失；退出登录不删除本地工具数据。

### 阶段 D：远程服务发布

- 在满足备案、HTTPS、邮件域名认证、监控、备份和回滚条件后部署。
- 接入桌面端浏览器登录与 Credential Manager 凭据保存。
- 验收：远程服务故障时客户端退回本地模式；生产日志无敏感内容；发布可回滚。

## 13. 测试要求

- 前端：Vitest 覆盖本地状态、侧栏排序、卡片、笔记、同步队列和冲突状态；Playwright 覆盖桌面/Web 尺寸、键盘操作、离线与恢复网络。
- 后端：JUnit/Mockito 覆盖领域规则与应用服务；Testcontainers 或隔离测试 PostgreSQL 覆盖 Flyway、MyBatis-Plus、JSONB、鉴权、限流、乐观锁与冲突接口。
- 桌面端：pytest 覆盖桥接白名单、Hosts 安全边界、配置原子写入和单实例；Windows 10/11 手工验证 UAC、WebView2 缺失提示和浏览器登录回调。
- 发布：前端类型检查、单元测试、构建；后端测试和 JAR 构建；PyInstaller 构建、EXE 冒烟、ZIP 内容和 SHA-256 校验。

## 14. 待确认决策

## 15. 需求变更原则

- 新工具必须通过编译期工具注册表接入，不能破坏现有工具 ID、固定标签和快捷方式兼容性。
- 涉及同步范围、隐私边界、删除策略和登录方式的变更必须更新本文档及 API 契约，并在实现前评审。
- 数据库迁移一旦用于共享或生产环境，只能新增迁移，不能改写历史版本。
- 前端视觉重构以任务效率、可访问性和多尺寸可用性为验收基础，动效不作为单独的功能目标。
